# 产品背景与确定要求

## 用户问题

目标用户是在日本养老介护现场工作的外国职员，首批优先验证就职初期或现场会话吃力的人。产品帮助其问清指令、尊重利用者的拒绝、清楚报告，并在具体回合复练。不要按国籍或JLPT等级直接推定工作能力。

学习者在手机上练习；企业教育担当者在电脑网页上分配任务、查看约定的数据和安排下一步辅导。购买者可能是个人，也可能是设施长、法人培训负责人或相关培训机构。

## 用户明确要求

1. 正式上架应用商店，而不只交付网页或PWA。
2. 个人与企业使用相同学习功能；企业享批量优惠，额外增加管理能力。
3. 场景应丰富、接近实际行动和沟通，具有自然分支、实时AI语音及个别指导。
4. UI现代、专业；重视手机语音交互、反馈和复练，而不止聊天窗口。
5. 这是长期项目，工程、成本和交接必须支持持续迭代。不能把数次对话或一次原型构建当成项目完成。
6. 方案需包含视觉假想、功能页面、交互、可行性及销售路径；已有25页方案与交互设计可继承。
7. 用户关心开发期OpenAI费用，要求将它与ChatGPT订阅、上线后的学员训练成本及其他费用分开。
8. 最近要求先查成熟免费开源代码再考虑定制；本包附初筛结果。

## 建议保留的产品区别

- 从实际沟通难点出发：确认含糊指令、接住拒绝、说明已知和未确认事实。
- 场景包含已知/隐藏信息和教学目标，回应有分支。
- 反馈引用学员原话，给一个清楚的下一步，并对薄弱回合复练。
- 使用留出的变式题检查迁移，而非只背参考句。
- 企业端帮助担当者选择下一次辅导，不把练习音频全面变成员工监控。

上述区别是待验证的产品主张，不是已证实的教学效果或竞争优势。通用AI、HAi-J、免费教材和相邻产品已有相关能力，不能宣传市场空白。

## 内容与视觉

现有48个虚构场景、8类、144个参考表达和4个会话变式，均为草稿。第一批应深审12个场景，再扩大。

目标视觉采用柔和纸白、紫色和薄荷绿；学习入口、场景简报、暗色语音页面、引用原话的反馈、复练与企业周辅导视图。具体以PDF和可编辑HTML为参照；允许根据真机可用性调整。

首版使用虚构案例，不上传真实利用者介护记录。它是语言训练产品，不承担临床建议、介护能力认证或独立上岗认定。

# 运行与迁移

## 现有工程

- TypeScript、React 19.2.6、Next 16.3.4、Vinext 1.0.0-beta.5、Vite 8.0.13、Cloudflare Workers。
- Node要求`>=22.13.0`；包管理器固定`pnpm@11.25.0`。版本以`prototype/package.json`与锁文件为准，不是升级建议。
- `vite.config.ts`保留本地Cloudflare和Sites插件；相关插件源码及已有许可文件随原型一起保存。
- 原工程使用pnpm锁文件；先复现，再决定是否更换框架或包管理器。

## Claude外部环境的启动路径

确认Node和指定pnpm版本可用后，在`prototype/`目录执行：

```sh
pnpm install --frozen-lockfile
node node_modules/typescript/bin/tsc --noEmit
pnpm build
pnpm dev
```

便携模式的开发脚本指定端口5173。清洁副本缺少本机执行配置时，`scripts/execution-profile.mjs`默认`portable`。以终端实际输出为准，先验证无密钥的演示路径。

这组外部环境命令尚未在用户的Mac/Claude环境中验证。本次实际安装与构建发生在ChatGPT Work的Linux环境，使用其受支持的构建工具。原README中的Sites监督器/发布流程仅适用于原环境。

`install:ci`的旧Linux脚本依赖`flock`、GNU `timeout`等，不应直接作为macOS通用安装说明；常规pnpm安装优先。如果配置引用了本机共享缓存，将缓存配置调整为当前机器的私有可写位置，保留依赖和锁文件的安全策略。

## 凭证

`configuration/env.example`仅列环境变量名，没有可用密钥。演示无需真实AI凭证。真实调用时应由用户在安全本地配置或部署平台的秘密变量中提供凭证，不发到聊天。

原代码从Workers `env.OPENAI_API_KEY`或服务端`process.env.OPENAI_API_KEY`读取。原会话确认过的本地目标为`.env.local`；外部环境还需验证框架和Wrangler是否实际注入该值，必要时按其官方说明配置本地Workers变量。不要把密钥放到浏览器可见的`NEXT_PUBLIC_`或`VITE_`变量。

原私有站点的运行时密钥、平台登录、源仓库临时授权和API余额不能由ZIP转移。这里没有授权创建新密钥、充值或进行无人值守付费负载实验。

## 原平台与新开发环境

源码来源提交与原Site标识见`verification/provenance.json`。原Git服务依赖平台授权，不是一个已授予Claude访问权的GitHub仓库。

建议将完整目录放在用户控制的私有仓库，建立未改动基线，再建开发分支。保留`prototype/.openai/hosting.json`作为原始快照；新部署应独立配置目标，不把旧站点ID自动复用于新平台。

新手机客户端可以复用内容、类型、规则与部分服务端逻辑；React网页UI不能直接当作原生App界面。客户端选型应先验证录音、打断、后台切换、耳机、弱网及内购，再确定迁移范围。

- 局部复练和未见变式题；避免仅优化模板答句。
- 既有标签目标仅是待测目标：一致样本关键标签匹配≥85%、重点漏项检出≥90%、误报≤10%。不构成已证实效果。

## G2：商用基础

九个工作包：手机客户端、AI语音、教学场景、账户与学习数据、企业管理、订阅与用量、云端基础、内部运营、测试发布。

具体应包括：
- 用户、组织、设施、成员与角色；独立账号验证跨组织读写导出均被拒绝。
- 个人练习与企业任务的可见范围；加入/退出企业不删除个人账号或私有学习记录。
- 商店购买/恢复/续费失败/退款；企业合同与席位；同一人有多种付费来源时定义额度使用顺序。
- 验证购买和通知；重复、乱序、延迟、漏通知补查不重复授予权益。
- 用量先校验/预留、再结算；并发不能超领；客户额度与供应商费用分别记账。
- 内部运营可以审稿发布、撤回场景、处理争议、查看错误与成本；敏感支持操作留审计记录。
- 开发、验收和生产环境分离；锁定依赖，兼容数据库迁移，备份恢复，版本回退。

## G3：受控试点

目标招募2-3个独立设施、约8-20名学员，运行范围明确的4周试点；目前没有这些客户或订单。验证使用、误评、复练、迁移、担当者时间、真实成本和付费续费。

## G4：上架与逐步扩容

- 商店账号、安装包、隐私与AI数据共享说明、同意记录、删除、订阅说明和客服流程齐备。
- 真机、企业隔离、支付、用量、恢复和故障路径通过，再逐步放量。
- 初步容量试验假设：约100名日活/10路同时语音；再验证1000日活/50路；更大规模重新估算和测试。当前全部未验证。
- 正常网络语音首段响应P95≤3秒；约定负载下非AI接口P95≤500毫秒、服务端错误率<1%，均为目标。
- 后端24小时稳定性测试与真实语音分批测试分别预算；供应商限流/停机、进程重启和通知重放需要验证。
- 恢复点≤24小时、恢复时间≤4小时只是初期目标，必须演练，不能提前写成SLA承诺。
- 首次扩大商用前，对企业权限、支付、关键数据和恢复做独立工程复核。

# 商业与费用边界

## 已确认方向

个人从App Store/Google Play购买；企业批量采购享优惠，并增加管理后台。相同的学员学习功能、内容和基础语音额度。企业共享分钟属于可选的透明分配方式。

企业直接合同的收款与App权益需要按上架地区及商店规则落实。Apple企业服务条款有适用条件；Google仅消费模式不能原样套到有内购的混合App。日本外部支付也有资格、披露、报告和费用条件。归档只保留截至2026-10-23的研究，提交前重新核对。

## 待验证价格

- 个人示例：1,980日元/月，60分钟实时语音。
- 企业10席示例：16,800日元/月，共600分钟；每席1,680日元，较10份个人订阅低约15%。
- 4周试点示例：9,800日元，最多10名，共300分钟，含明确范围的初始化和结项复核。

这些是报价假设，用户没有确认正式售价。旧版24,800日元/10席的企业高单价方向已被替换。不得恢复成企业学员更贵或功能不同的方案。

按照此前估算语音0.02-0.06美元/分钟、仅作换算1美元=150日元，600分钟约1,800-5,400日元。它不是官方固定分钟报价，也不是毛利：需按选定API/型号和实际用量重新测算，另计税、商店/支付费、后台模型、云服务、客服、退款及获客。

## 开发期OpenAI预算

前期建议工作预算300美元、规划区间150-500美元，针对既定原型至内测范围，覆盖内容和提示词、文字功能、独立评测、语音比较及少量工具试验。先充值50美元只是建议，不是已执行支付或持续消费授权。

新增商用负载测试、长周期语音、供应商迁移要重新估量。它不是整个商业App的总开发费用，也不含上线后的学员正常训练用量。

普通ChatGPT/Codex或Claude订阅内的开发工作，不自动等于应用的API消费。另用API编程代理或外部付费工具时单独核算。Claude Pro开发工具订阅与应用生产调用费用分开。

最近一次已记录API生成受余额不足阻塞，未确认后续充值；本次归档没有API调用、充值或购买。不得把旧余额读数当作现在余额。

## 销售验证

企业路径：可接触设施→4周小试点→付费续费→同法人复制→成熟后拓伙伴。个人入口同步验证自然试用与续订。两家独立付费续费作为扩大销售前的初步信号，当前尚无订单或效果数据。

export async function openai(path:string,body:unknown){
 const key=apiKey();if(!key)return json({error:'AI接続の準備が必要です。デモで操作を体験できます。',code:'not_configured'},503);
 try{
  const r=await fetch('https://api.openai.com/v1/'+path,{method:'POST',headers:{Authorization:`Bearer ${key}`,'Content-Type':'application/json'},body:JSON.stringify(body),signal:AbortSignal.timeout(45000)});
  if(!r.ok){let code='api_error';try{const j=await r.json() as {error?:{code?:string}};code=j.error?.code||code;}catch{}
   const msg=['insufficient_quota','credit_balance_exhausted'].includes(code)?'AIサービスの利用残高がありません。デモで操作を体験できます。':r.status===401?'AI接続の認証を確認する必要があります。':r.status===429?'AIが混み合っています。少し待って、もう一度お試しください。':'AIに接続できませんでした。会話は残っています。もう一度お試しください。';
   return json({error:msg,code},r.status===429?429:502);
  }
  return r;
 }catch{return json({error:'接続に時間がかかっています。もう一度お試しください。',code:'connection_error'},502);}
}
