# 工作包与验收顺序

## G0：复现与一条真机链路

- 复现构建、脚本演示、API未配置提示；保留原型可用基线。
- 核查模型生命周期，集中配置型号，用固定样本比较迁移结果。
- 选择一条真实现场难点场景，验证iOS/Android语音会话、字幕、打断、停止、断线和费用。
- 服务端保留密钥、授权与会话控制；正常结束或失败后都能确定状态和用量，不依赖前端计时器。
- 费用、平台账号或真机确实阻塞时，明确最小依赖；先继续不依赖它的工作。

## G1：教学闭环

- 深审12个核心场景；每个具备目标、已知/隐藏信息、分支、示例/反例、反馈规则、迁移题和版本。
- 初步60段对话由介护经验者与日语教育者独立标注，分歧单列。
- 反馈引用真实发话；接受等价回答，误听可纠正，证据不足时明确不确定。
- 局部复练和未见变式题；避免仅优化模板答句。
- 既有标签目标仅是待测目标：一致样本关键标签匹配≥85%、重点漏项检出≥90%、误报≤10%。不构成已证实效果。

## G2：商用基础

九个工作包：手机客户端、AI语音、教学场景、账户与学习数据、企业管理、订阅与用量、云端基础、内部运营、测试发布。

具体应包括：
- 用户、组织、设施、成员与角色；独立账号验证跨组织读写导出均被拒绝。
- 个人练习与企业任务的可见范围；加入/退出企业不删除个人账号或私有学习记录。
- 商店购买/恢复/续费失败/退款；企业合同与席位；同一人有多种付费来源时定义额度使用顺序。
- 验证购买和通知；重复、乱序、延迟、漏通知补查不重复授予权益。
- 用量先校验/预留、再结算；并发不能超领；客户额度与供应商费用分别记账。
- 内部运营可以审稿发布、撤回场景、处理争议、查看错误与成本；敏感支持操作留审计记录。
- 开发、验收和生产环境分离；锁定依赖，兼容数据库迁移，备份恢复，版本回退。

## G3：受控试点

目标招募2-3个独立设施、约8-20名学员，运行范围明确的4周试点；目前没有这些客户或订单。验证使用、误评、复练、迁移、担当者时间、真实成本和付费续费。

## G4：上架与逐步扩容

- 商店账号、安装包、隐私与AI数据共享说明、同意记录、删除、订阅说明和客服流程齐备。
- 真机、企业隔离、支付、用量、恢复和故障路径通过，再逐步放量。
- 初步容量试验假设：约100名日活/10路同时语音；再验证1000日活/50路；更大规模重新估算和测试。当前全部未验证。
- 正常网络语音首段响应P95≤3秒；约定负载下非AI接口P95≤500毫秒、服务端错误率<1%，均为目标。
- 后端24小时稳定性测试与真实语音分批测试分别预算；供应商限流/停机、进程重启和通知重放需要验证。
- 恢复点≤24小时、恢复时间≤4小时只是初期目标，必须演练，不能提前写成SLA承诺。
- 首次扩大商用前，对企业权限、支付、关键数据和恢复做独立工程复核。

原12周安排是初步试点节奏；新增原生App、支付与商用工程后，应按实际工作重新估时。
