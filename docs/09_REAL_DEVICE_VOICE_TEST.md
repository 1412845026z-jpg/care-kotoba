# 真机语音训练闭环测试方案（G0，2026-10-23 起草）

目的：在 iPhone 和 Android 手机上，用真实的 OpenAI Realtime 跑完一条「开口 → AI 回应 → 打断 / 断线 → 结束 → 引用原话的反馈」闭环，并留下可复核的证据。代码侧已经准备好：访问保护、服务端挂断、转写排序、断线后恢复、诊断日志导出（docs/08）。**本方案还没有执行过。**

## 需要用户决定的事项（目前阻塞）

| 决定 | 为什么需要 | 建议 |
| --- | --- | --- |
| 1. 是否授权一笔测试预算 | 真实调用会产生 API 费用 | 为 G0 设上限 10 美元（估算见下文），在 OpenAI 控制台为测试单独建一个项目和密钥，并按控制台实际提供的选项设置预算提醒或上限 |
| 2. 由谁、在哪里配置密钥 | 密钥不能出现在聊天、仓库或截图里 | 用户本人在部署平台的 secret 设置中填写；测试结束后在控制台撤销该密钥 |
| 3. 部署到哪里 | 手机上的 `getUserMedia` 要求 HTTPS（安全上下文） | 按 DEPLOY-001（Codex）准备的方案，部署到新的私有 staging，不复用旧 Sites 站点 |
| 4. 测试人员与设备 | 需要至少 1 台 iPhone 和 1 台 Android | 记下机型、系统版本和浏览器版本 |

不做这些决定也能继续推进的工作：离线测试、CI、部署方案文档、内容审稿，以及下面的免费真机测试。

## 先做免费的真机测试（2026-10-24 用户指示：能免费就免费，付费往后放）

服务器不设置 `OPENAI_API_KEY` 时，AI 接口会回答「未设置」，应用改用演示模式。下面这些项目都可以在真手机上测，AI 费用为 0。需要付费的 T1–T14 等用户另行授权后再做。

### 让手机打开应用的方式（都不花钱）

| 方式 | 适合 | 怎么做 | 限制 |
| --- | --- | --- | --- |
| A. 电脑本地运行 + Android USB 转发 | Android | 电脑上按 docs/10 的本机步骤运行开发服务器（不设 API 密钥）。手机用 USB 连接电脑，在电脑 Chrome 打开 `chrome://inspect` → Port forwarding，把手机的 5173 转到电脑的 5173，然后在手机上打开 `http://localhost:5173` | 对手机来说这是 localhost，属于安全上下文，麦克风可以用。不部署，不对外公开。iPhone 不能用这种方式 |
| B. 电脑本地运行 + 同一 Wi-Fi | iPhone 和 Android 的界面检查 | 手机打开 `http://<电脑的局域网 IP>:5173` | 不是 https，手机浏览器不允许使用麦克风，只能测界面、文字和演示 |
| C. 不设 API 密钥的私有 staging | iPhone 和 Android 的全部免费项目 | 按 docs/10（Codex）的 Workers Free + Access Free 方案部署，不设置 `OPENAI_API_KEY`，设置 `CK_ACCESS_CODE` | 部署要用户另外授权；Workers Free 是否够用还没有在云上测过 |

### 免费测试项目

| ID | 内容 | 方式 | 记录什么 |
| --- | --- | --- | --- |
| F1 | 首页、场景、笔记、学习记录在手机上显示正常，没有横向滚动，注音显示正常 | A/B/C | 截图（不含个人信息）、机型和浏览器版本 |

「声で入力」用的是手机浏览器自带的语音识别，不经过 OpenAI，应用不付费。但声音可能由浏览器提供商（Google、Apple 等）的服务器处理，第一次使用时应用会说明这一点，并请学员确认。手机键盘本身的语音输入也可以用，但它跟随键盘语言，外国学员常常需要先切换到日语键盘。

## 最小安全配置（staging）

| 变量 | 作用 | 是否机密 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 服务端调用 OpenAI | 是 |
| `CK_ACCESS_CODE` | 测试访问码，至少 6 个字符，可用逗号分隔多个；只告诉测试人员 | 是 |
| `CK_SESSION_SECRET` | 签名用的密钥（可选；不设置时由 API 密钥派生）。随机 32 字节以上 | 是 |
| `CK_VOICE_MAX_SECONDS` | 单次语音会话的上限，默认 180；T8 临时设为 60 | 否 |
| `CK_VAD` | `server`（默认，静音 700 毫秒）/ `server-slow`（1200 毫秒）/ `semantic-low` | 否 |
| `CK_MODEL_TEXT` / `CK_MODEL_REALTIME` / `CK_MODEL_TRANSCRIBE` / `CK_MODEL_TTS` | 覆盖型号；G0 先用默认值 | 否 |

确认方式：打开 `/api/health`，应看到 `configured: true`、`access.policy: "code"`，以及各型号距停用的天数。返回内容中不会出现密钥。

不要使用 `CK_ACCESS_POLICY=open`，除非站点前面已经有平台级访问控制。

## 费用估算（未经实测）

按 gpt-realtime-mini 每百万 token 的价格：音频输入 10 美元、缓存 0.30 美元、输出 20 美元（音频价格按 gpt-realtime-2.1-mini 推定，见 `lib/cost.ts`），转写约 0.003 美元/分钟。一次约 3 分钟、8 个来回的会话，估计 **0.03–0.10 美元**；每次文字反馈不到 0.01 美元。完成下面全部测试大约 30–40 次会话，合计约 1–4 美元。实测以诊断日志中的 `estimatedCostUsd` 和 OpenAI 控制台当日用量为准，两者都要记录。

## 部署后先跑的接口冒烟测试

staging 部署好以后，先在电脑上运行 `node tools/smoke/api-smoke.mjs --base https://<staging>`。这一步不花钱：只检查 health 和访问码，访问码用 `CK_SMOKE_ACCESS_CODE` 传入，不会打印出来。用户授权费用后，再加 `--yes` 跑一次。这会调用一次对话、一次反馈和一句 TTS，费用只有几美分，并检查反馈引用的是否都是学员原话。语音（WebRTC）不在这里测，用下面的手机测试。

### 核心场景草稿的角色检查（CORE-EVAL-001，需授权费用）

如果要用核心场景草稿（「コア練習（草稿）」），在 api-smoke 之后运行 `node tools/smoke/core-roleplay-check.mjs --base https://<staging>`。

- 不加 `--yes` 时只列出计划（28 个探测），不花钱。
- 授权后加 `--yes`（可以再加 `--repeat 3 --out report.json`）。每个探测调用一次文字模型，共 28 次，费用只有几美分。
- 自动检查三项：
  - 问清场景里，学员只是答应或乱猜时，角色有没有提前说出隐藏信息；
  - 学员认真问了之后，角色有没有说出；
  - 拒绝场景里，学员施压时，角色有没有说出理由。
- 判断方法只是检查回复里有没有特定词，所以报告里标为 review 的探测（是否继续礼貌地拒绝、报告场景有没有补造原因）要人工阅读回复。
- 一次运行只是样本，不能当作比例。结果记在 MODEL-001 / DEVICE-001。

## 测试用例

**开始前（不花钱）**：在每台手机上打开「学習設定」→「音声テスト（マイク・スピーカー）」，依次检查浏览器支持、服务器与访问码、WebRTC 候选、麦克风音量和扬声器（自报是否听到），点「結果を保存（JSON）」，和下面各用例的诊断日志放在一起。这一步不连接 AI（`lib/voice-preflight.ts`，2026-10-24 加入）。任何一项为 ×，先解决再进行付费的 T1–T13。

每次测试结束后，在反馈页点「音声テストの診断ログを書き出す」（断线时也可以在错误提示中点「診断ログ」），保存 JSON 文件。服务端日志会出现 `voice_session_start` 和 `voice_session_end` 两条记录（Cloudflare 可以用 `wrangler tail` 或控制台日志查看）。

| ID | 操作 | 观察与记录 | 通过标准（G0） |
| --- | --- | --- | --- |
| T1 | 场景「お顔を拭く前のひとこと」，用扬声器，说 4–6 个来回后点「終了して振り返る」 | 能否听到开场白；对话记录的顺序；反馈是否引用了实际说过的话 | 两个平台各 3 次：顺序没有错误，能听到开场白，反馈中的「あなたのことば」都是原话 |
| T2 | 句子中间故意停顿 1–2 秒；分别用 `CK_VAD=server`、`server-slow`、`semantic-low` 各做 3 次 | 被 AI 抢话的次数（主观记录）；诊断日志中的 `latency` | 选出抢话最少、等待也不太长的一种，作为默认候选 |
| T3 | AI 说话时插话 | AI 是否在 1 秒内停下；该条是否标「途中で中断されました」；`bargeIns` 计数 | AI 停下，标记正确 |
| T4 | 静音 / 取消静音 | 静音期间 AI 是否还在回应 | 静音期间不触发回应 |
| T5 | 通话中切换 Wi-Fi 和 4G，或开 5 秒飞行模式 | 是否先显示「接続が不安定です」，然后恢复，或显示「切れました」+「音声で再接続」；重连后是否接上之前的对话 | 要么恢复，要么能重连并保留之前的对话；服务端日志有挂断记录 |
| T6 | 锁屏或切到其他 App 10 秒后回来 | 实际表现（iOS 可能挂起）；诊断日志的 `connection` | 记录表现即可（不作为通过条件），用于原生客户端选型 |
| T7 | 用有线 / 蓝牙耳机，与扬声器对比 | 扬声器模式下 AI 是否听到自己的声音而打断自己 | 记录差异 |
| T8 | `CK_VOICE_MAX_SECONDS=60` | 60 秒时是否自动结束；服务端 `voice_session_end` 中 reason 为 `max_duration`，hangup 为 `done` | 自动结束且已挂断 |
| T9 | 通话中直接关掉标签页 | 服务端是否出现 reason 为 `pagehide` / `closed` 的结束记录 | 有挂断记录；没有的话记下来（已知限制） |
| T10 | 语音通话中用键盘输入一句 | AI 是否回应；记录中标为文字输入 | 能回应 |
| T11 | 故意说一句发音含糊的话，再用「聞き取りを修正」改正 | 反馈是否区分「识别错误」和「语言问题」；是否引用了修正后的文字 | 不把明显的识别错误当成语言错误 |
| T12 | 用错误的访问码 → 正确的访问码；不输入访问码直接体验演示 | 提示文字是否正确 | 错误的被拒绝，正确的可以进入，演示不需要访问码 |
| T13 | 首次使用时拒绝麦克风权限 | 是否提示改为文字练习 | 不会卡住 |
| T14 | `CK_ASR_LOGPROBS=1`（默认关闭）：T1、T11 各做一次，并故意含糊地说一句带部位或数字的话 | 诊断日志中每句的 `asrMean` / `asrMin`（只有数字，不含文字）；含糊的那句是否显示「聞き取りに自信がありません」；有没有出现社区报告过的噪音或 logprobs 缺失 | 清楚的句子不误报、含糊的句子能标出；据结果校准 `lib/asr-confidence.ts` 的阈值，再决定是否默认开启 |

## 还没有覆盖的
