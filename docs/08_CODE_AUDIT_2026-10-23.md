范围：`prototype/` 中学员端、AI 接口和语音链路相关的源码（`app/api/**`、`lib/**`、`components/**`、`app/page.tsx`）。Sites 模板文件（`lib/connector*`、`components/ui/*`、`scripts/`、`worker/`）只做了阅读，没有审计其安全性。这是一次接手时的工程检查，**不是安全审计**，也不能证明可以商用。

## 怎么得出的结论

1. 从交接 TXT 和后来导入的 ZIP 里取得源码，原样建立基线（PR #1，130 个源码文件逐一校验）。
2. 无法安装依赖（本环境访问 npm 仓库被拒），所以搭了离线测试环境：用 esbuild 打包**真实的** `app/page.tsx` 和**真实的** API 路由，配一个模拟的 OpenAI 服务，在 Chromium 里按 390×844 手机尺寸和桌面尺寸操作。语音部分让第二个 Chromium 页面通过**真实的本机 WebRTC 连接**扮演 Realtime 服务器，按官方 GA 事件格式发送事件。细节和边界见 `prototype/tests/README.md`。
3. 先写测试复现问题，并在**未修改的基线**上运行：20 项中 15 项失败（`verification/G0-01/baseline-tests.*`）；修复后同一组测试全部通过，另加 33 项单元测试（`verification/G0-01/after-tests.*`）。

测试编号对应 `verification/G0-01/*.tap.txt` 中的 TAP 序号。以下「已修复」均指在上述离线 / 模拟环境中通过，**没有经过真实 AI、真机或真实网络的验证**。

## 按严重程度排序

### P0｜在原私有平台之外部署前必须处理

| # | 问题 | 证据 | 处理 |
| --- | --- | --- | --- |
| 1 | 所有花钱的 AI 接口（chat / feedback / speech / session）没有任何身份或访问检查。`validateOrigin()` 在请求不带 Origin 时直接放行，所以 curl 之类的工具可以无限调用，消耗 API 余额。原站点靠 Sites 平台外层登录保护，迁到独立域名后这层保护就没有了。 | 基线上 `/api/chat` 无 Origin、无凭证时返回 200（测试 #1） | **已修复（试运行级别）**：新增访问保护 `lib/access.ts`。设置了访问码就要求访问码，没设置就只允许 localhost，未配置的公网部署会拒绝 AI 调用。访问码换取 HttpOnly + SameSite=Strict 的 HMAC 签名 Cookie；更换访问码会让旧 Cookie 全部失效；猜码有频率限制；另外按路由做了单实例内存限流。**仍缺**：真实账户、组织与角色、按人的持久额度（需要数据库，属于 G2）。 |

## 保留什么、重做什么

- **可以保留**：场景内容和数据结构（待审稿）；学员端的信息架构和视觉；脚本演示；服务端「密钥只在服务器」的路由划分；文字对话与反馈的结构化输出；本轮新增的转写排序、会话控制、反馈校验、访问保护和测试环境。原生 App 也可以复用这些纯逻辑模块（`lib/realtime-transcript.ts`、`lib/feedback-quality.ts`、`lib/voice-metrics.ts`、`lib/cost.ts`）。
- **商用前必须重做或新增**：真实账户、组织和角色，以及数据库；按人 / 按组织的用量预留与结算；服务端强制会话控制（旁路连接 + 持久存储）；与 OpenAI 用量对账；原生客户端（录音、后台、耳机、内购）；生产安全验收和错误监控。
- **不应据此宣称**：「可以商用」「支持某个用户规模」「反馈准确」「真机可用」。这些都还没有证据。

## 本轮没有做的检查

- 项目自身的 `pnpm install --frozen-lockfile`、`tsc --noEmit`、`pnpm build`（交给 CI-001）。离线替代检查是：服务端和纯逻辑模块用 TypeScript strict 模式 + `cloudflare:workers` 桩做类型检查；组件对照宽松的 React 桩检查，向其中注入错误已确认能被检出。
- vinext / Next 的 SSR、Cloudflare Workers 运行时下的环境变量注入（ENV-001）。
- 真实 OpenAI 调用、真机、iOS Safari / Android Chrome、弱网、计费。
