## 用量和费用算式

下列 token 数是预算假设，不是实测；日文字符不能直接等同 token。当前 `/api/chat` 每次 `max_output_tokens=750`，反馈为 1400；输入 6,000 token/调用仅为本次短对话预算，不是服务器强制上限。实时每次回复 `max_output_tokens=500`，也不等于整个会话总量的硬上限。

文字模型总调用 **48 次**＝冒烟 2＋核心探测 28＋人工文字 3×(4＋1)＋语音后反馈 3。共 41 次 chat 和 7 次 feedback：

- 输入：48×6,000＝**288,000 token**。
- 输出：41×750＋7×1,400＝**40,550 token**，按当前输出上限预留。
- 费用：(288,000×0.40＋40,550×1.60)/1,000,000＝**$0.18008**。

实时语音 3 次，每次按累计（包括历史重新输入）文字输入 24,000、文字输出 400、音频输入 5,000、音频输出 1,200 token 预算：

- 累计文字输入 **72,000** / 输出 **1,200**；音频输入 **15,000** / 输出 **3,600**。
- 条件费用：(72,000×0.60＋1,200×2.40＋15,000×10＋3,600×20)/1,000,000＝**$0.26808**。
- 额外转写：学员发声 3 分钟×$0.003＝**$0.009**。

官方 Realtime 用量指南说明用户原始音频约 600 token/分钟、AI 音频约 1,200 token/分钟；**后续回复还会计入已有会话上下文**，所以只乘新说出的分钟数会漏算历史。这里音频输入 15,000 token 已预留历史重复输入，不再把“3 分钟×600”当作总输入。本计划不使用 GPT-Live 的按秒计费规则估算当前 Realtime 会话。[S6]

单句 TTS 预算假设输入 100 token、输出音频 1,000 token：**$0.01206**。这不是把 MP3 时长套用 Realtime 音频 tokenizer 得出的值；若实际合成 token/时长超过假设，应更新记录并停止追加请求。

## 批次与停止条件

执行必须有人全程看守，只有一个窗口发请求；不用 CI、计划任务、循环或并发测试。每批开始前查看已结算花费和当前在途请求。**建议人工停止线 $1（预算口径约 ¥240 含预留）；总授权建议仍为 ¥1,000。** 低停止线为计量延迟和未及时挂断留余量，未用额度不补测。

1. 用户自行在平台选择专用测试项目，只允许本次需要的型号；如果平台提供硬限额，建议设项目 **$3 硬限额**、$0.50 与 $1 告警，禁止自动充值。未确认硬限额实际启用前，不进入真实调用；平台选项不足时先交接，不能把提醒当硬停止。
2. 当前官方文档支持可选 **Enforce a hard limit**：仅设置告警仍会继续请求；硬限额也存在传播延迟，可能稍微超出。不能承诺绝对不会超出某一日元数，不能只靠平台设置。[S9]
3. api-smoke 是一个最多 3 个计费调用的批次。core 检查**逐场景**运行（每批 2–3 次调用），每批后停下查账；不要无 `--scene` 一口气执行完整 28 次。现有工具收到单个失败不会马上终止后续探测，操作人发现费用/连接异常要中断进程，仍需核对已经在途的调用。
4. 每次人工文字练习后核对；每次语音 120 秒或 4 次 AI 回复先到就正常结束，确认 `/api/session/end` 挂断为 `done` 或 `already_ended`，关闭连接后再开始下一次。不用刷新重试或后台留着通话。
5. **立即停止整个试验：** 已计费＋在途保守预留达到 $1；费用记录迟迟不可见或无法对上；一次 2 分钟语音估算超过 $0.20；预计下一批会碰到停止线；总用量/次数/时长达到计划；出现 401/429/余额不足/未知型号价格；真实敏感信息进入对话；挂断失败、计时器异常或页面被杀掉无法确认结束。
6. 停止后不自动重试、不提高限额、不充值、不换贵型号。操作人正常结束会话；用户在平台禁用本测试密钥或测试项目访问，并核对提供方后续入账。密钥停用能否立即终止已建立的实时会话尚未验证，不能当作挂断确认。问题与未结算金额记录清楚后，另请用户决定。

当前 App 仍没有可信的按人持久用量账本、与提供方对账、被杀页面的服务端强制时长。浏览器计时/客户端 `estimatedCostUsd` 不能承担商用扣费或硬预算保证（docs/08 #3/#19）。

## 每个学员每月 AI 成本公式（用于以后定价）

定义：`N文字`/`N语音`＝每月各类练习次数；`C文字`/`C语音`＝按真实样本得到的平均每次美元成本；`C额外TTS`＝不已包含在这两项里的朗读；`f重试`＝失败/重连等的额外用量比例；`R`＝每美元实际日元成本；`f结算`＝适用税费/汇率等缓冲。则：

```text
每学员每月AI成本JPY = R × (N文字×C文字 + N语音×C语音 + C额外TTS)
                      × (1 + f重试) × (1 + f结算)
```

每次成本以各模态相加：

```text
C文字 = ((非缓存输入×输入价) + (缓存输入×缓存价) + (输出×输出价)) / 1,000,000
C语音 = Σ实时各模态的非缓存/缓存输入和输出token×对应价 / 1,000,000
        + 单独转写成本 + 该次文字反馈成本
```

累计 `usage.input_tokens` 通常已包含缓存部分，必须先拆分，不能先按总输入收费又额外加缓存。转写按token或按分钟二选一，避免同一项重复计算。只听已缓存的本机音频不重新调用模型时，该次AI增量成本0；不要把云TTS重新生成混入0成本。[S6]

用本次**假设而非实测**举例：1次文字＝4回合chat＋1反馈，输入30,000/输出4,400，`C文字=$0.01904`；1次2分钟语音及反馈 `C语音=$0.09700`（旧实时音频价仍条件估算）。每月20次文字＋12次语音，以R=200、重试预留25%、结算预留20%，约 **¥463.44/学员/月**。这仅是给定使用量下的AI可变成本，不是订阅售价，也不含运营、商店抽成、客服、存储或利润；正式定价要换成试验实测均值、长尾/重度用户和最新单价。
