# 信息来源与核实状态评测草稿（EVAL-002）

草稿，待介护经验者与日语教育者审稿。全部是虚构、独立的文字评测片段，无录音、无真实学员数据，未运行任何模型或API。

`samples.jsonl`有12条、6组配对：每组的已给事实和学员发话完全相同，只更换一条合适反馈与一条有问题的反馈。这样能检查评分者是否真的读了反馈，而非只凭“学员说得好”判一切通过。配对ID不得作为模型输入；`expected_*`、候选正误和理由也不得泄露给被测模型。

这些片段与12场景中的能力有关联，但不是修改应用内场景的版本。`scenario_anchor`只用于归类；评测时只提供本条`facts`和`learner_turn`，不能自动加载原场景的隐藏信息。

## 两个维度

`expected_information`按具体断言列出：

- `source_kind`说明信息来自本人陈述、学员观察、同事传话、无来源推断或不确定转写。
- `verification`说明这条具体断言是否被当前片段支持，或仍未成立，或转写不足。

`supported_by_context`不是“临床上已经证明”，只表示当前给定证据支持对应断言。例如“本人说过痛”可获支持；“痛是撞伤引起”仍未成立。不能把“本人感受”直接变成“未确认”，也不能把前班的话改写成自己整夜观察的事实。

## 评分方法

这里的`candidate_feedback_ja`是给离线评审者或后续评分模型检查的固定候选，不是已经从生产模型拿到的结果。后续若评测实际反馈生成，应只给事实和发话，生成后再按相同门槛人工审阅；本轮没有这样运行。

| 门槛 | 要检查的内容 | 失败例 |
| --- | --- | --- |
| `quote_attribution` | 反馈声称引用学员时，是否逐字来自可靠的U1，而非角色、参考答案或猜测的转写 | 把无法辨清的“痛い/痛くない”补成确定原话 |
| `source_and_verification` | 是否逐断言区分来源与核实状态 | 主观信息一律未确认；传闻当成自己的观察 |
| `bounded_inference` | 观察的时间、对象和范围是否被保留 | 一餐剩饭推成几天食欲下降；发现坐在地上推成已目击跌倒 |
| `respect_refusal` | 是否允许尊重拒绝作为成功结局 | 要求反复追问或说服到同意才通过 |
| `transcript_uncertainty` | 关键转写不可靠时是否先确认或暂不评分 | 猜否定词、硬判学员报告错误 |

`not_applicable`不进入该门槛分母，不表示已经通过。凡该样本适用的门槛出现失败，应单独列出，不用其他得分抵消。未提供录音时作出发音判断，另标`pronunciation_claim_without_audio`。

每组分别报告：好反馈被错拒的次数、坏反馈被误放的次数、对同一上下文两种候选的区分情况。对转写不确定组，另看是否硬评分或编造原话。原话引用正确只是必要检查之一，不证明反馈内容正确。

`feedback_evidence`是专业评审对反馈/复练时可引用的可靠学员片段；不是候选坏反馈已经正确使用过的证据。转写不可靠时必须为空。接受其他合适的措辞，不要求模型背出这一参考反馈。

## 本地检查与后续使用

`python3 evals/source-confidence/validate.py`只检查数据合同、来源引用、配对不变量和可靠逐字引用，不评价语言与教学质量。它不调用API，不是通用JSON Schema引擎。

后续真实评测要记录数据文件SHA-256、提示版本、模型快照、设置、日期和实际费用；保留原始返回和人工复核，分别报告确定标签与不确定样本。没有费用授权时只准备输入，不执行模型调用。内容仍需介护经验者与日语教育者共同审稿后才可当作校准后的评测标准。
