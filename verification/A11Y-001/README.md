# A11Y-001｜手机上的可读性（对比度、字号、点击区域、输入缩放）

环境：Claude 沙箱，Chromium 153 headless，离线 harness + 模拟 AI，视口 390×844（另查 320 / 360 / 375 / 414 的横向溢出）。`audit.mjs` 是抽查，不是完整的 WCAG 审计，也没有用屏幕阅读器。

| 检查（7 个画面：首页、场景列表、场景详情、文字练习、反馈、笔记、学习记录） | 修改前 `before.json` | 修改后 `after.json` |
| --- | --- | --- |
| 正文对比度低于 WCAG AA（4.5:1；大字 3:1）的文字，每个画面去重后计数 | 21 / 21 / 29 / 30 / 37 / 14 / 17 | 全部 0（只剩装饰用的 ✦ 符号） |
| 点击区域小于 24×24 px（WCAG 2.5.8 AA） | 1 / 1 / 2 / 7 / 5 / 3 / 1 | 全部 0 |
| 字号小于 16px 的输入框（iOS Safari 聚焦时会放大页面） | 搜索框 9px | 0 |
| 注音（rt）字号 | 6.5px | 至少 9px |
| 360px 及以下的横向溢出 | 4px（首页推荐卡片的负边距，原有问题） | 0（320 / 360 / 375 / 390 / 414 都已核对） |

做法：在 `prototype/app/globals.css` 末尾加了一个「可读性层」。每种文字颜色保持原来的色相，按审计结果调深到 AA；窄屏上提高最小字号和点击区域。删掉这一块就能恢复原样。小于 44×44 的点击区域还有一些，作为建议值，不是 AA 的要求。

截图（2 倍像素密度）：`a11y-modal-390.png`、`a11y-feedback-390.png`、`a11y-context.png`。图标是测试环境的占位方块。

不证明：真机上的观感、屏幕阅读器朗读顺序、动态字号设置、深色模式。
