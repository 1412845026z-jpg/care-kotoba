## 跨场景的主要问题（按优先级）

1. **同名人物左右矛盾。** CK-P01 是中村さん「左のひざ」。但关联术语卡 CK-T016 的例句，以及锚定 CK-P01 的评测 CK-I001、I002、I009、I010，都写成中村さん「右膝」。部位正是本课程要求学员确认的信息。建议统一为左，或在独立片段里改用另一个虚构姓名。
2. **常见错误样本太极端。** 「嫌でも入ってください」「わがままを言わずに」「関節炎です」这类很容易识别。N4 学员在现场更常见、更难察觉的错误没有覆盖，建议补进 common_error：
   - 只答应不问：「はい、分かりました。」（C01、C02）
   - 假装听懂：「はい、更衣ですね。」（C03）
   - 软性施压：「でも、入ったほうがいいですよ」「少しだけ食べましょう」「どうしてですか？」（R01、R02）
   - 漏掉信息来源，把本人诉说当成事实：「中村さんはひざが痛いです。」（P01）
   - 把发现时的状态说成事件：「〇〇さんが転倒しました。」（P03）
   - 把传闻混进自己的观察：「夜は起きていました。」（P04）
3. **NPC 台词不像角色本人。**
   - C 组 B2 的「依頼の内容をもう一度確認しましょう。何が分かっていて…」是教练口吻，会替学员开口。应让 NPC 留在角色里，把提示放到反馈中。
   - R 组 B3 的「私の気持ちを聞いてほしいです」对日本高龄者来说过于直白。
   - R 组 B2 四个场景共用「必要なときはこちらから伝えます」，建议改成各场景具体的说法。
4. **请求放慢时没有真的放慢。** C 组 B3 与 B1 回复相同。学员请求放慢或分段时，NPC 应该真的分段重说。
5. **例句碰巧说中隐藏信息。** CK-R01 例句「今はお休みになりたいですか」正好命中隐藏信息，会让评分倾向奖励猜中理由。建议改成中性问法。
6. **语音模式下的前提。** CK-C02 用「……」表示听不清，但 TTS 只会念成停顿。接入语音时需要单独设计。
7. **可接受的再提议。** R 组建议把不施压的再提议列为可接受，例如「また後で伺ってもいいですか」「担当の方に伝えますね」，与施压区分开。
8. **术语卡。**
   - 很多例句没有出现词头本身（傾聴、受容、摂取、摂食、意欲、拒否等）。建议补一句含词头的职员间用例。
   - 片假名词的读音写成平假名（こみゅにけーしょん、りすく）。建议只给汉字注音，并采用应用已有的 `{漢字|かんじ}` 标记，这样能直接用 `tools/furigana/` 生成和核对。
   - 「主観的事実／客観的事実」与 SOAP 记录常用的「主観的情報／客観的情報」哪个更合适，请日语教师和介护经验者确认。
9. **评测覆盖面。**
   - 全部是单轮样本。建议加入多轮样本：先漏问、经提示后补问，测试反馈能否肯定这次修正。
   - 加入简体但含义正确的样本（如「何の準備ですか？」），测试「不以敬语复杂度为唯一标准」。
